# XRay_MSU

Расчёт порошковой рентгеновской дифракции для заданной кристаллической структуры: отражения, структурный фактор, кратность, L/P-факторы, нормировка, свёртка пиков (Кальотти + профиль). Есть **консольный сценарий** с конфигом OmegaConf и **GUI** на Tk/matplotlib.

**Подробное описание алгоритма:** [doc/README.md](doc/README.md).

## Требования

- **Python ≥ 3.12**
- Рекомендуется **[uv](https://docs.astral.sh/uv/)** (`uv sync`). В `pyproject.toml` задано `python-preference = "system"`, чтобы по возможности использовать системный интерпретатор с рабочим **tkinter** (на Linux см. `packaging/check_linux_tkinter_ldd.py` и пакеты `python3-tk` / `python3.12-tk`).

## Установка

```bash
git clone <url> XRay_MSU && cd XRay_MSU
uv sync                    # или: make install
uv sync --group dev        # PyInstaller для сборки бинарников
```

## Запуск

| Задача | Команда |
|--------|---------|
| CLI с конфигом по умолчанию (`config/alpha-Fe_structure.yaml`) | `uv run python cmd/main.py` или `make run` |
| CLI с **своим** YAML (первый аргумент — путь от корня репозитория) | `uv run python cmd/main.py config/Cu.yaml` |
| GUI | `uv run python -m src` или `make gui` |

### Конфигурация YAML (основные поля)

Параметры читаются через **OmegaConf** (`cmd/main.py`). Имя образца задаётся ключом **`name`** — по нему создаётся каталог **`runs/<name>/`**.

| Поле | Смысл |
|------|--------|
| `a`, `b`, `c` | Длины рёбер ячейки (Å) |
| `alpha`, `beta`, `gamma` | Углы ячейки (градусы) |
| `space_group` | **Hall number** в базе **spglib** (см. ниже), не путать с «номером 1–230» из International Tables без проверки |
| `bravais_centering` (или устар. `cubic_bravais`) | Только **GUI** при загрузке YAML: при **`space_group: null`** — развернуть узлы по типу центрирования в долях **a,b,c**: **`none`**, **`P`**, **`I`**, **`F`**, **`C`**, **`A`**, **`B`**. Имеет смысл при **α≈β≈γ≈90°** (куб, тетрагон, орторомб и т.д.), не только для куба |
| `atoms` | Список строк `[символ, x, y, z, occupancy, B_iso]` — дробные координаты в асимметричной части |
| `wavelength` | Длина волны (Å), обычно Cu Kα ≈ 1.5418 |
| `twotheta_range` | `[2θ_min, 2θ_max, шаг]` в градусах |
| `U`, `V`, `W` | Коэффициенты Кальотти для полуширины пика |
| `thetam_deg` | Угол монохроматора (поляризация **P**) |
| `scale` | Общий масштаб интенсивности |
| `profile` | Профиль линии: например `bar`, `gaussian`, `pvoigt` |
| `eta` | Доля Лоренца в псевдо-Фойгте (если применимо) |
| `normalize_intensity` | Нормировать ли интенсивности пиков к `intensity_max_value` |
| `intensity_max_value` | Максимум после нормировки (условные единицы) |
| `intensity_min` | Порог: пики с расчётной интенсивностью **строго ниже** этого значения **не попадают** в таблицу `*.tsv`. Значение **`0`** оставляет в таблице и **запрещённые** рефлексы (нулевой **F** и интенсивность) |
| `multiplicity_mode` | `symmetry` — кратность по орбите точечной группы в **G**\*; `metric` — объединение индексов с тем же \(1/d^2\) в кубе (см. [doc/README.md](doc/README.md) §4.4) |
| `multiplicity_metric_rtol`, `multiplicity_metric_atol` | Допуски сравнения \(1/d^2\) в режиме `metric` |

Если в YAML нет **`intensity_min`**, в CLI подставляется **`1e-6`**.

**Про `space_group`:** в коде вызывается `spglib.get_spacegroup_type(number)` — аргумент — это **серийный номер символа Холла (Hall number)** в базе spglib (единицы с **международным номером 1–230** не совпадают). Например, для кубической группы **Fm-3m** в примерах используется **523**; если подставить **225** как «международный номер», spglib интерпретирует его как **другой** Hall-номер и даст **другую** группу. Проверяйте вывод в консоль (международное имя и Шёнфлиса) или таблицу Hall в документации spglib.

### Файлы в `runs/<name>/`

| Файл | Содержимое |
|------|------------|
| `<name>.tsv` | Таблица рефлексов (см. ниже) |
| `G.csv`, `Gstar.csv` | Метрика прямой решётки **G** и сопряжённая **G\*** |
| `<name>_powder.png` | Кривая \(I(2\theta)\) после свёртки + подписи углов \(2\theta\) у пиков |
| `<name>.png` | Схематичное изображение ячейки и атомов |

После расчёта из GUI набор файлов тот же.

### Столбцы таблицы `<name>.tsv`

| Столбец | Обозначение |
|---------|-------------|
| `hkl` | Индексы Миллера (представитель «орбиты» в выбранном режиме кратности) |
| `d` | Межплоскостное расстояние (Å) |
| `twotheta` | Позиция пика, \(2\theta\) (°) |
| `mult` | Кратность (режим `symmetry` или `metric`) |
| `l` | Фактор Лоренца **L** |
| `p` | Фактор поляризации **P** |
| `lp` | Произведение **L·P** (для физического пика в допустимой геометрии **не обнуляется**) |
| `F` | Структурный фактор (в файле для \|F\|≈0 выводится **`0`**; чисто вещественные пики — без лишней мнимой части) |
| `intensity` | Интенсивность после множителей и при необходимости **нормировки** |
| `intensity_units` | Подпись единиц (при нормировке добавляется пометка `normalized`) |

Конфигурации-примеры лежат в **`config/`** (YAML), таблица атомных факторов формы **f₀** (Waas–Kirfel) — **`data/f0_WaasKirf.dat`**.

**Алгоритм** (структурный фактор, свёртка, Кальотти, режимы кратности) подробно разобран в **[doc/README.md](doc/README.md)**.

## Сборка бинарников (PyInstaller)

- **Linux:** `make dist-gui` / `make dist-cli` или `./packaging/build-ubuntu.sh` — GUI в виде каталога `dist/xray-msu-gui/`, CLI — один файл `dist/xray-msu-cli`.
- **Windows:** `make dist-win` или `packaging/build-windows.ps1` / `build-windows.bat` → `dist/*.exe`.

Подробности в комментариях к `packaging/*.spec` и в `make help`.

## GitHub Actions и релизы

- Workflow **[build-binaries](.github/workflows/build-binaries.yml)** на push в `main` (по путям исходников) собирает артефакты для **Windows** и **Linux**; вложения можно скачать на вкладке **Actions**.
- По push тега **`v*`** запускается **[release](.github/workflows/release.yml)**: в одном run собираются **windows** и **linux**, затем job **publish** скачивает артефакты и создаёт **GitHub Release** с `xray-msu-gui.exe`, `xray-msu-cli.exe`, `xray-msu-linux-amd64.tar.gz`.

Создание релиза:

```bash
git tag -a v0.1.0 -m "0.1.0"
git push origin v0.1.0
```

Для записи релизов у репозитория в **Settings → Actions → General** должны быть разрешены права workflow на запись в репозиторий (по умолчанию для `GITHUB_TOKEN`).
